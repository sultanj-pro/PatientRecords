About Me

I'm an engineering leader with deep experience at the intersection of software architecture and organizational design. I've guided engineering teams through every growth stage, and the common thread across all of them has been the same challenge: how do you keep velocity high as complexity grows?

My answer has always been to design systems and org structures together. Architecture that fights your team topology always loses. PatientRecords is the living proof-of-concept of that philosophy: a production-grade reference implementation that demonstrates how Module Federation, microservices, and AI multi-agent patterns combine to let independent teams ship independently without sacrificing coherence.

Outside of work, I'm drawn to problems that sit at the edge of what software can do in high-stakes domains — which is why clinical decision support became the subject matter for this case study. Complex data, real consequences, demanding UX requirements, and strict correctness constraints make it the perfect proving ground for architectural ideas.

About This Project

PatientRecords is a production-grade clinical reference architecture built to answer a concrete question: what does a well-scaled, multi-team system actually look like end-to-end?

It is not a toy demo. Every layer is fully implemented:

  • ● Micro-Frontend Shell — 6 Angular MFEs + 1 React MFE running side-by-side via Module Federation, demonstrating true technology-choice independence for frontend teams.
  • ● Microservices Backend — 15 independent Node/Express services, each containerised, each with its own Swagger docs, covering the full clinical domain.
  • ● AI Multi-Agent Pipeline — An orchestrator fans out to specialist agents (medication, labs, LLM narrative), streams results over SSE, and requires physician approval before any recommendation is acted on.
  • ● Real-Time Escalation — Redis Streams consumer evaluates 10 clinical rules on every domain write; matched rules surface as WebSocket-pushed notifications with 24-hour deduplication.
  • ● Dual-Adapter Data Layer — Switch between PostgreSQL and MongoDB with a single environment variable. Zero code changes required.

The full source is open on GitHub. Clone it, run it with docker compose up -d, and explore.
